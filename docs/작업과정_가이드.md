## 1. 테마 준비와 첫 배포

1. Hugo Themes에서 **CareerCanvas** 저장소의 `Code → Download ZIP`으로 받아 압축을 풉니다.
2. 수업에서 받은 `prepare_github_pages.py`를 그 폴더에 복사하고 실행합니다.
   ```bash
   python prepare_github_pages.py
   ```
   저장소 주소를 물으면 `https://github.com/HyangnamDexter/Introducemyself`를 입력합니다.
   - 이때 **"ZIP 버전이 전체 빌드 검증 목록과 일치하지 않습니다"** 경고가 나왔다면, 스크립트가 빌드 보정 파일을 만들지 않았다는 뜻입니다(아래 2단계 문제의 원인).
3. Git 연결과 push는 직접 합니다.
   ```bash
   git init -b main
   git remote add origin https://github.com/HyangnamDexter/Introducemyself.git
   git add .
   git commit -m "init"
   git push -u origin main
   ```
4. GitHub 저장소의 **Settings → Pages → Build and deployment → Source**를 `GitHub Actions`로 바꿉니다.

## 2. 첫 배포 실패 해결 (Tailwind 설정 누락)

**증상**: Actions의 `Build and fix project URL paths` 단계가 빨간색으로 실패했습니다.

**원인 찾는 법**: 같은 Hugo 버전(0.167.0 extended)을 받아 `site/` 폴더에서 같은 명령으로 빌드하면 오류가 그대로 재현됩니다.
```
POSTCSS: failed to transform "/css/main.css": postcss config "./postcss.config.js" not found
```
테마가 CSS를 Tailwind(PostCSS)로 만드는데 그 설정 파일이 ZIP에 없었습니다. 예전에 성공했던 프로젝트와 비교하면, 그때는 준비 스크립트가 `package.json`, `postcss.config.js`, `tailwind.config.js`를 만들어 줬지만 이번 ZIP은 더 새 버전이라 검증 목록과 맞지 않아 만들어 주지 않았습니다.

**해결**: `site/`에 세 파일과 `package-lock.json`을 추가하고 push했습니다. 커밋 `6ccbc03`.

> **Windows에서 로컬 빌드할 때 주의**: Hugo가 Node를 권한 모드로 실행하는데, 드라이브 문자 대소문자가 다르면(`C:` 와 `c:`) `ERR_ACCESS_DENIED`로 실패합니다. `cmd`에서 `cd /d c:\users\...\site`처럼 **소문자 드라이브**로 이동해서 실행하면 됩니다. GitHub Actions(Linux)에서는 문제가 없습니다.

## 3. 테마 원본은 두고 "덮어쓰기"로 고치기

Hugo는 `site/layouts/`에 테마와 **같은 경로·이름의 파일**이 있으면 그 파일을 우선 사용합니다. 그래서 테마(`site/themes/template/`)는 손대지 않고, 고칠 파일만 복사해서 수정했습니다.

```bash
# 예: 상단 메뉴를 고치고 싶을 때
cp site/themes/template/layouts/partials/nav.html site/layouts/partials/nav.html
# 그 다음 site/layouts/partials/nav.html 을 수정
```

이렇게 고친 주요 문제와 위치:

| 문제 | 고친 파일 |
|---|---|
| `<html lang="en">` 고정 → 한국어 사이트인데 언어가 영어로 표시 | `site/layouts/_default/baseof.html` |
| 메뉴 클릭이 주소(#about)를 바꾸지 않아 **뒤로 가기**가 안 됨 | `site/layouts/partials/nav.html` |
| 아이콘만 있는 버튼·링크에 이름이 없음 (스크린리더가 읽지 못함) | `nav.html`, `hero.html`, `footer.html` |
| 푸터 이름 링크가 `/#home`(도메인 루트)로 이동 | `site/layouts/partials/footer.html` |
| 프로필 이미지 경로가 도메인 루트를 가리킴 | `site/layouts/partials/hero.html` (`relURL` 사용) |
| 소개 페이지가 없으면 스크립트 오류 | `site/layouts/partials/about.html` |
| 실제로 전송되지 않는 문의 폼 | `site/layouts/partials/contact.html` (연락처 목록으로 교체) |
| 키보드 초점이 잘 안 보임 | `site/assets/css/site.css` |
| 계속 움직이는 애니메이션을 멈출 수 없음 | `site/assets/js/motion-control.js` (멈춤 버튼) |
| 기술 아이콘이 배포 후 깨짐 (빌드 스크립트의 경로 보정이 JS 문자열을 바꿔 버림) | 아이콘 SVG를 `site/static/images/icons/`에 직접 넣음 |
| 라이트 모드에서 상단 글자가 흰 배경에 흰 글씨 | `site/assets/css/site.css` (상단 배경 지정) |
| 링크 미리보기 제목에 "careercanvas"가 남음 | `site/pages.json`의 `title` 삭제 |

## 4. 내 정보와 활동 작성

| 바꾸고 싶은 것 | 파일 |
|---|---|
| 이름, 한 줄 소개, 짧은 소개, 지역, 이메일, GitHub | `site/hugo.toml` |
| 자기소개, 관심 분야와 이유, 학습 목표와 다음 행동 | `site/content/ko/about.md` |
| 역량 카드 | `site/content/ko/skills.md` |
| 활동 타임라인 | `site/content/ko/experience.md` |
| 대표 활동 상세 페이지 | `site/content/ko/activities/personal-website.md` |
| 기술 아이콘 | `site/content/ko/technical.md` (+ `site/static/images/icons/`) |
| 프로필 사진 | `site/static/images/profile.jpg` |

**사진 넣는 법**: 정사각형으로 자른 뒤(640px 정도) `site/static/images/`에 넣고, `hugo.toml`의 `profile_image = "images/파일명"`으로 지정합니다. 경로 앞에 `/`를 붙이지 않아야 `/Introducemyself/` 아래로 연결됩니다. 휴대폰 사진에는 위치 정보(EXIF)가 들어 있을 수 있으니 다시 저장해서 지우는 것이 안전합니다.

**새 활동 추가하는 법**: `site/content/ko/activities/`에 `.md` 파일을 하나 더 만들고, `experience.md`의 `positions:`에 항목을 추가한 뒤 `detail_url`에 그 페이지 주소를 적습니다.

## 5. 수정 → 커밋 → 배포 → 확인

```bash
git add <수정한 파일>
git commit -m "무엇을 왜 바꿨는지 설명"
git push origin main
```

1. 저장소 **Actions** 탭에서 실행이 자동으로 시작되고 `build`, `deploy`가 초록색이 되는지 확인합니다.
2. 사이트를 `Ctrl+F5`로 새로고침해 변경을 확인합니다.

**커밋은 작업 단위로 나눠서** 합니다. 채점기준(P51~P53)이 "실제 내용이 바뀐 커밋 50개 이상"과 "커밋 메시지가 실제 변경을 설명하는지"를 봅니다. 숫자 채우기용 커밋(같은 내용을 바꿨다 되돌리기 등)은 제외됩니다.

## 6. 공개 사이트 점검

```bash
pip install playwright
python tools/verify_site.py docs/verification
python tools/a11y_check.py > docs/verification/axe_result.json
```

`docs/verification/`에 화면 캡처(1440·768·390px, 메뉴, 키보드 초점, 확대, 활동 페이지)와 결과 로그가 생깁니다. 보고서의 그림과 기능 검증표는 여기 결과를 그대로 씁니다. 사이트를 고친 뒤에는 **다시 실행해서 캡처를 갱신**하세요.

손으로 확인할 때는 다음을 해 보세요.
- 로그인하지 않은 시크릿 창에서 사이트 열기
- 메뉴를 하나씩 눌러 보고 뒤로 가기
- 개발자 도구(F12) → 기기 모드에서 폭 390px로 메뉴 열고 이동
- 마우스 없이 Tab, Enter, Esc만으로 이동
- `Ctrl` + `+`로 200% 확대

## 7. 보고서 작성과 제출

1. 보고서(`2026_과제1_보고서_202212980_이승환.docx`)에서 **제출 정보의 SHA·커밋 URL·Actions URL**이 실제 최종 `main`과 같은지 확인합니다.
   ```bash
   git log -1 --format=%H        # 최종 전체 SHA
   git rev-list --count HEAD     # 전체 커밋 수
   ```
2. **보고서를 만든 뒤에 사이트를 더 고쳤다면** SHA, 커밋 수, Actions URL, 캡처 시각을 모두 새 값으로 바꿔야 합니다.
3. Word에서 **파일 → 다른 이름으로 저장 → PDF**로 `202212980_이승환_과제1.pdf`를 만듭니다.
4. PDF를 직접 열어 그림이 보이는지, 링크가 클릭되는지 확인하고 LMS에 1개만 올립니다. 마감: **2026-10-31 23:59 KST**.
